Install the development snapshot reviewed on 28 November

For the current vcp seal repairs, install the implementation revision below with Python 3.10+ and Git. It is the pin selected by README main 1e75820e954eda7232bc57eb21037efaa1cbf1ba; it is not the fixed v0.1.0 tag. Package metadata remains 0.1.0, so retain the commit as well as the version.

python -m pip install --force-reinstall "git+https://github.com/veritaschain/vcp-sdk.git@59860c5d3180ac8bdc2e8b9df500af7ae2c162f7#subdirectory=python"

This revision preserves optional top-level PolicyIdentification and rejects a non-object or a PolicyID that disagrees with Header.PolicyID before signing. Registration metadata such as ConformanceTier remains unsigned. Preserving it does not authenticate it. Two-file output replacement remains non-atomic; consult VCP SDK: current source and pinned installation for staging, rollback and crash recovery.

For TypeScript, check out the same commit and build with Node 20+. Copy MQL5 files from that checkout. First-party main CI at the stated README revision recorded Python 356 tests plus 6 subtests on each tested version, TypeScript 169 tests and Wine MQL5 199 self-tests; these are separate checks, not independent reproduction or Windows-native/broker validation. See the versioned result table and 28 November announcement. The earlier commands below are retained for historical evaluations.

15 November: output-collision repair and evaluation revision

SDK #18 adds preflight rejection of collisions between seal outputs, input evidence and key files, including relative paths, symlinks and hard links. It does not provide a concurrency lock or an atomic multi-file transaction.

To evaluate this repair, the Python example below selects the exact merged source revision. This is development source, not a new tag or PyPI package.

python -m pip install --force-reinstall "git+https://github.com/veritaschain/vcp-sdk.git@0832f1d84af9b130db6a17d36c343a8abd7002a8#subdirectory=python"

Record the full commit, inputs, trust and dependency environment. The earlier installation snapshot and tags remain unchanged.

Read changes, revisions and limits · SDK #18

Read three-valued results

  • VALID: a performed check matched.
  • INVALID: a checked mismatch or malformed input.
  • INDETERMINATE: required trust, external proof or support is missing. Not a pass.

Aggregation prioritizes INVALID, then INDETERMINATE, then VALID. Without supplied and verified external anchoring, the full batch remains INDETERMINATE.

Capabilities and boundaries

The core covers canonical hashes, Merkle proofs and Python/TypeScript Ed25519 operations. MQL5 has a smaller feature set; do not assume identical signing and verification support.

Exact-integer handling, RFC trees and root-only signature coverage are documented in SDK implementation choices and verification limits. These implementation choices are not adopted VSO requirements.

The SDK does not contact services, establish real-world key ownership, prove all actions were captured, guarantee decision safety or validate the full JSON Schema. The SDK Explorer evidence demo is also a synthetic example, not a production audit.
