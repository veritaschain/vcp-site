実行・受領・版の選択

写真・証明の受領とSDK評価に使う日英の実務ページです。VeraSnap Verify SDKとVCP SDKは別の実装です。

このページの従来の導入例は記載日の版を保持しています。2026年11月26日に確認したmain・固定タグ・MQL5の自社CIの状態は、下記の版一覧で区別して確認してください。

  • VeraSnap Verify SDK実行ガイド — 固定コミットと合成例で結果を保存する
  • 写真・証明の受領担当者ガイド — 原本保存・個別チェック・追加確認の手順

版の一覧には11月26日・27日の記録を残し、11月28日確認のmain・固定タグ・自社CIの状態を追記しています。

公開されているのは開発ソース

固定 v0.1.0 プレリリースが存在します。以下で導入するのはその後の開発ソースで、パッケージの版表示は 0.1.0 のままです。VSOはこれらのパッケージをPyPI・npmへ公開していません。VCP SDK Specificationに記載されたクラウド／Explorerクライアントとは別です。

VeritasChain株式会社による自社実装であり、外部実装・認証済み製品・独立検証ではありません。VCP SDK: current source and pinned installation を参照してください。

11月28日確認の開発版を導入する

現行の vcp seal 修正を使う場合は、Python 3.10以降とGitで次の実装版を導入してください。READMEのmain 1e75820e954eda7232bc57eb21037efaa1cbf1ba が示す導入対象であり、固定 v0.1.0 タグとは別です。パッケージ表示は 0.1.0 のままなので、版番号とコミットの両方を残してください。

python -m pip install --force-reinstall "git+https://github.com/veritaschain/vcp-sdk.git@59860c5d3180ac8bdc2e8b9df500af7ae2c162f7#subdirectory=python"

この版は任意のトップレベル PolicyIdentification を保持し、オブジェクトでない場合や、その PolicyID が Header.PolicyID と不一致の場合は署名前に拒否します。ConformanceTier などの登録メタデータは、保持されても署名対象外です。 保持だけでは真正性を確認できません。2ファイルの置換は単一の原子的な処理ではないため、一時保存・ロールバック・異常終了からの復旧は VCP SDK: current source and pinned installation を確認してください。

TypeScriptは同じコミットをチェックアウトしてNode 20以降でビルドし、MQL5もそのチェックアウトからコピーします。記載したREADMEのmainでの自社CIは、対象Python版それぞれ356テスト・6サブテスト、TypeScript169テスト、Wine上のMQL5自己試験199件の成功を記録しています。異なる検査であり、独立再現やWindowsネイティブ・ブローカー接続の確認ではありません。版別の結果表 と 11月28日のお知らせ を参照してください。以下の過去の導入コマンドは履歴として保持します。

11月27日の導入例（履歴）

vcp seal を使う場合は、Python 3.10以降とGitで次の開発版を導入してください。すでに 0.1.0 を利用している場合も同じコマンドで更新できます。

python -m pip install --force-reinstall "git+https://github.com/veritaschain/vcp-sdk.git@28d46e8491f6ff819f1cfe7c31895ed7ad7df3ff#subdirectory=python"

この版は署名前にバッチ内のポリシーIDの一致を確認し、両方の出力を準備してから保存先を置き換えます。異常終了時の復旧手順は VCP SDK: historical 27 November source and installation にあります。

TypeScriptは同じコミットをチェックアウトしてNode 20以降でビルドし、MQL5もそのチェックアウトからコピーします。評価記録には完全なコミットIDを残してください。

11月15日：mainの上書き防止修正と評価する版

SDK #18で、vcp sealの出力同士、入力証拠、鍵ファイルの衝突を事前に拒否する修正がmainへ入りました。相対パス・シンボリックリンク・ハードリンクを検査しますが、同時実行のロックや複数ファイルの原子的な保存を保証するものではありません。

今回の修正を評価するPython導入例は次の固定コミットを使います。新しいタグやPyPIパッケージではなく開発ソースです。

python -m pip install --force-reinstall "git+https://github.com/veritaschain/vcp-sdk.git@0832f1d84af9b130db6a17d36c343a8abd7002a8#subdirectory=python"

評価記録には完全なコミット、入力、信頼設定、依存環境を残してください。従来の固定導入版・タグは変更していません。

更新内容・対象版・限界を読む · SDK #18

三値の検証結果を読む

  • VALID：実施した確認が一致したこと。
  • INVALID：確認できた不一致や不正な入力。
  • INDETERMINATE：信頼する鍵、外部アンカー証拠、対応機能などが不足。合格ではありません。

集約の優先順位はINVALID、INDETERMINATE、VALIDです。外部アンカー証拠と検証機能が与えられなければ、完全なバッチ結果はINDETERMINATEのままです。

できることと限界

正規化ハッシュ、Merkle証明、Python／TypeScriptのEd25519署名などを扱います。MQL5側は機能範囲が異なり、同じ署名・検証機能を一式備えるとは限りません。

整数を正確な桁で処理する選択、RFC方式の木、根だけの署名範囲などはSDK implementation choices and verification limitsに記録された実装上の扱いです。VSOによる規範採択ではありません。

SDK自身は外部へ接続せず、鍵の実在人物への帰属、全行動の捕捉、判断の安全性、完全なJSON Schema適合を証明しません。公開ExplorerのSDK Explorer evidence demoも、実運用の監査結果ではありません。
