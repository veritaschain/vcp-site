What this page establishes

VeraSnap apps, the receiving-side Verify SDK, the public Explorer, and the website/contact channels are separate processing systems. This guide helps enterprise and insurance teams identify which information goes where and who controls retention, access and deletion.

Review scope: public documents and selected source revisions reviewed on 28 November 2026. We did not measure traffic from distributed app binaries, audit operating environments, or establish actual retention periods or storage countries. Statements below distinguish published descriptions, source observations and items requiring deployment-specific confirmation.

This explanatory guide does not replace the privacy policy, app terms or an individual agreement. VSO is a specification initiative operated by VeritasChain Co., Ltd. This page is not evidence of certification or an independent audit.

Map the data route first

  1. Capture device: creates media and its proof. Timestamp requests involve an external time-stamping authority (TSA).
  2. Submission: the user shares or exports originals and proofs through the organization's approved intake channel. Email, business applications and cloud-storage services have their own handling conditions.
  3. Receiving system: the organization supplies proofs, required photos, a key registry and trust configuration to Verify SDK in its controlled environment, then retains the results.
  4. Decision: record technical findings separately from business decisions. Define access, retention and deletion for originals, results and submitter-to-record mappings.

This is an integration-planning example, not a deployed customer case. The embedded Capture SDK remains at the design stage. See app and SDK roles and the receiving workflow.

Public Explorer: synthetic data and connections

Source observation: the selected public Explorer entry describes synthetic events and the SDK Evidence Demo. The latter sends requests to the configured API at veritaschain-evidence-demo.kamimura0000.chatgpt.site for the case list and the selected synthetic case's verification result. Page loading also involves ordinary hosting and font-delivery requests. Public Explorer — deployed entry and external resource configuration Public Explorer — selected bundle, API requests and local storage

The bundled API client includes a facility to save an API key in browser localStorage when configured and attach it to API requests. Do not treat that storage as an encrypted secret vault. Use synthetic data with the public demo; it is not an intake channel for business credentials or customer evidence.

Unconfirmed: API/delivery-provider log retention, actual storage countries and operational evidence of deletion. This source review is not an audit of the API environment. A successful demo response or display does not establish complete external-anchor verification or independent reproduction.

This API-key setting belongs to a bundled client separate from the Evidence Demo retrieval code. This review confirms the capability in source; it did not register or transmit an API key.

Website and contact transmissions

The website privacy policy separates hosting, external assets, inquiry delivery and optional analytics. Forms backed by Formspree transmit their entered fields to that service; email links open the user's email environment. VSO website privacy policy — analytics and service providers

Source observation: the shared VSO analytics loader starts the Google Analytics tag after consent. It removes URL fragments and unapproved query fields, allowing only specified campaign fields. It does not copy inquiry text into its custom event parameters. An email-link click is not evidence that an inquiry was delivered. VSO website analytics — consent and URL filtering implementation

Declining analytics still leaves requests needed to deliver pages, images and fonts. A particular page or external destination can have processing separate from this loader.

This page makes no unlisted commitment about storage country, retention, response deadlines, certification or service levels. Leave unconfirmed items marked as such and use your organization's process to decide whether real data may be introduced. Review the app terms separately from the Verify SDK's Apache-2.0 license.

Discuss the unresolved items

For an initial inquiry, send the product/revision, workflow outline, intended data route and questions to resolve. Leave out customer photos, claim documents, personal data, private keys and API keys. Agree the channel and scope before sharing confidential material.
