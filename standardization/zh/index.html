第一部分

当前状态的诚实陈述

VeritasChain Protocol (VCP) 的设计充分考虑了 IETF RFC 兼容性。VSO 目前有五份有效的个人 Internet-Draft（draft-kamimura-vap-framework-02、draft-kamimura-scitt-vcp-05、draft-kamimura-rats-behavioral-evidence-02、draft-kamimura-scitt-refusal-events-04、draft-vso-cpp-core-04），均未被任何 IETF 工作组采纳，也不具有任何 IETF 地位。

本页面介绍 VCP 所基于的技术前提，以及我们所设想的未来标准化路径。

为什么这很重要

对标准化状态保持透明与 VCP 的核心理念一致：可通过密码学验证的记录，而非营销宣传。我们相信通过技术价值和运营记录来赢得信誉，而不是过早的公告。

第二部分

与现有RFC的技术对齐

VCP 的设计与以下 IETF RFC 兼容，支持 Internet-Draft 的编写，并与其他基于 RFC 的系统实现互操作。

RFC 8785

JSON规范化方案 (JCS)

确定性JSON序列化，确保所有实现中用于加密哈希的字节序列相同。

RFC 6962

证书透明度

遵循CT模式的Merkle Tree审计设计，实现高效的包含证明和篡改检测。

RFC 9562

UUIDv7

时间排序、可排序、全局唯一的标识符，带有嵌入时间戳，用于事件ID。

RFC 8032

Ed25519 签名

爱德华曲线数字签名，提供高安全性、优秀性能和紧凑签名。计划未来支持PQC。

RFC 3339

时间戳

ISO 8601兼容的日期/时间格式，确保系统间一致的时间戳表示。

FIPS 180-4

SHA-256

NIST批准的安全哈希算法，用于所有哈希链和Merkle Tree操作。

这种对齐支持Internet-Draft的编写和与其他RFC系统的互操作性。
