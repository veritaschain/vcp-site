27 October update: 159 API tests and the public inclusion demo

Updated 27 October 2026; earlier dated checkpoints are retained below.

API search: PR #20 rejects malformed non-pagination filters before data access and makes algo_id filter the available synthetic VCP-GOV records. PR #21 compares inclusive time boundaries as exact nanosecond integers, including equivalent numeric time-zone offsets, and rejects invalid or reversed time ranges with JSON 400 invalid_parameter. Original timestamp strings and fixtures are preserved. The bounded RFC 3339 input contract does not support leap seconds; it does not establish clock accuracy or agreement with a separate header.timestamp_int.

First-party CI for API main 3fce6a6 records 159 tests passed, zero failed, cancelled, skipped or todo: the prior 101 plus 36 filter cases and 22 time-search cases. The API CI log was checked for this publication; API tests were not rerun here. PR #22 also removes the package’s unsupported production-readiness / server-side proof-verification claim. This reference API returns demo events and proof fixtures; it does not perform server-side cryptographic verification. Repository merges and CI success do not establish production API deployment.

Public Explorer GUI: this publication incorporates GUI PR #20, source ed79ee8. Inclusion calculation now requires an explicit tree size, handles uneven branches and rejects invalid hashes, indices, sizes and missing or excess siblings. A response without a tree size is not verified. The screen and printable certificate carry the supplied size. The source’s 26 tests pass, including 189 leaf proofs across 14 tree sizes; 189 is a count of proof checks within the suite, not 189 additional tests. The same 26 tests, lint and the static-subpath build also passed locally for this publication.

The displayed proof uses a deterministic 12-leaf synthetic fixture. Its inclusion path can match the supplied root, but the root and size are not authenticated, and the fixture is unsigned, unanchored and not derived from the displayed event payload. Success means only an inclusion calculation against supplied inputs: event contents, signatures and external anchors have not been verified. The public GUI still uses synthetic data with no connected Explorer API. The original integrity-review warning and the existing print, contrast and notice-layout treatments are retained.

Status remains separate: VCP v1.2 is a published GA specification; that label does not establish implementation production suitability or full VAP conformance. VAP remains Draft 3. Experimental extensions remain unadopted, and independent third-party reproduction has not been established. First-party CI, local checks and website publication are not independent reproduction. 26 October, 23:29 JST: API input validation and development controls merged

Explorer API PR #18 was merged as e14c264 at 23:29 JST on 26 October 2026. It changes the API’s handling of pagination inputs, not only its development tools. Previously, inputs such as fractional limits and negative search offsets could be coerced or accepted. The corrected routes reject malformed or ambiguous limit / offset values with JSON 400 invalid_parameter before querying the data source.

The final reviewed-head CI on Linux x64, Node 24.22.1 and npm 11.19.1 passed lint, type checking, build and 101 tests, with zero failures, cancellations, skips or todo cases. These are 56 existing tests plus 45 new tests, not 101 new tests. The same HTTP regression first failed against the unchanged source and then passed after the correction. Its 57 HTTP observations cover 41 malformed inputs, 14 accepted requests and two backend-error responses. The corrected code rejects all 41 malformed inputs without calling the data source; accepted response bodies and the two genuine backend-error responses are unchanged.

Defaults for omitted inputs, leading-zero decimals, existing result caps and rate limiting are preserved. This is bounded pagination validation, not exhaustive validation of every query parameter or cryptographic evidence. The merged main CI also passed. These are first-party CI and review records; this website update did not rerun the API tests or establish independent reproduction.

Four preceding maintenance PRs were also merged: #12 updates ESLint while retaining existing checks; #14 updates and pins CI tools, retaining read-only repository access; #15 disables automatic dependency-install scripts and checks actual development startup/reload; #17 replaces two deprecated style rules with maintained rules and bounded diagnostic/fix comparisons. Explicit commands and imports can still execute dependency code: the install policy is not a sandbox.

Publication boundary: these merges and CI results do not confirm production Explorer API deployment. The public Explorer remains a synthetic demo with no connected API; its earlier UI publication checks are recorded separately below. A read-only check of saved reports

RTA PR #19 adds a maintainer aid that reads 17 fixed report files and checks them against the pinned reference: manifests, declared revisions, 29 declared input hashes, the exact 809 regression and 15 historical cases, execution and environment records, and the stable historical replay results. It does not run submitted code, rerun tests, extract archives or contact the network.

REPORTS_MATCH_REFERENCE means saved-report consistency only. Copied first-party reports or coherently fabricated reports can also match. The output keeps tests_rerun: false, independence: NOT_ASSESSED, publication_permission: NOT_ASSESSED and conformance_claim: false. Execution identity, assistance, independence and permission to publish still require separate review.

Browser printing and experimental tagged PDF output are different

The public Print / Save as PDF button invokes the native browser print dialog. It is not a validated tagged-PDF exporter. A separate first-party experiment compared default Playwright PDF output with an opt-in tagged:true file. The two-page files retained identical extracted text and rendered output in that bounded comparison, but only the opt-in file contained the observed structure tree and language metadata. That file was not produced by the public Print button.

GUI PR #19 documents these results and limits. Tag presence alone does not validate logical reading order, screen-reader usability or PDF/UA. Native browser-print accessibility remains unestablished; the document does not change the application’s export mechanism.

Legacy examples and SDK guidance: clearer limits

Sidecar examples are legacy v1.0 illustrations, not a production-ready or certified integration. Their Python serialization is not RFC 8785 JCS; the MQL5 placeholder hash is not SHA-256. Those examples do not implement signatures, Merkle construction or external anchoring. Documentation corrections do not repair the algorithms.

VCP documentation now distinguishes anchoring a root from authenticating batch metadata, and marks the retained duplicate-last Merkle example as historical and non-RFC. SDK guidance distinguishes the v1.0 Release Candidate specification from an informative v1.1 guide. The CAP refusal demo describes recording a refusal, not preventing content or capturing every action; its evidence remains NOT_ANCHORED.
