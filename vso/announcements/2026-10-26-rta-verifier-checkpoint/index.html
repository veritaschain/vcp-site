VSO publishes a fixed checkpoint for VCP RTA verifier review

VSO has published a fixed VCP RTA review target and now checked the published instructions end to end in its own CI, from a fresh public clone through final report assessment. The fixed 809 regression and 15 separate historical tests passed per environment. The 40-event evidence verdict remains INDETERMINATE. The supplemental format remains unadopted, and independent reproduction has not been established.

Implementation extension — unadopted; independent reproduction not established

The supplemental format is an implementation extension, not an adopted VCP/VAP format. This checkpoint is not a new release, certification or independent implementation. Neither its publication nor successful first-party CI establishes independent reproduction, full conformance or production suitability.

26 October update: published instructions checked in first-party CI

The additional PR #16 workflow completed in both Python 3.11 and 3.13.5 CI jobs on Ubuntu 24.04. It executes the published shell instructions without substitution: a fresh public clone, a new virtual environment, dependency installation, comparison of 29 input hashes, the fixed 809 regression and 15 historical cases, the 40-event replay, and final assessment of the saved reports.

The full procedure must complete successfully, while the evidence replay must return INDETERMINATE with exit code 2. Missing reports, setup failures or a zero shell exit without the required checks do not count as success. The launcher's 13 synthetic guard tests are separate from the fixed 809 + 15 cases. Repeating those cases in another workflow does not add new unique coverage.

The automation is maintained by the same project. These are two first-party environment runs, not two independent evaluators. Independent third-party reproduction remains unestablished; the supplemental format remains unadopted. The executed target stays cc695fe, the pinned guide stays a839d7a, and the automation is a separate revision. The workflow scope and retained-report description distinguish those revisions and the initial clone revision.

Logs and selected reports are retained for 30 days; this is not permanent archival or a fully locked environment. This announcement confirms published CI records, not a new local execution, independent review, certification or full evidence acceptance.

What changed in the verifier

The merged work separates VALID, INVALID and INDETERMINATE checks. Missing material cannot erase a separately detectable mismatch. Follow-up fixes validate Ed25519 keys and signatures, Merkle proof structure and timestamp policy inputs, bound inputs, and prevent a report from overwriting source evidence, keys or earlier reports. The regression runner also rejects unregistered test modules and inconsistent or malformed JUnit reports.

Ordinary verification and supplemental verification are separate

The ordinary CLI verifies signatures against a caller-supplied trusted key; it does not authenticate batch metadata or verify external anchors. A separate opt-in command checks signed supplemental records and offline RFC 3161 timestamps using caller-selected keys, CA certificates and TSA policy. A later supplemental timestamp does not establish the original logging or anchor time. Synthetic TSA checks are not live TSA interoperability results.

What the historical 40-event replay actually establishes

The corpus contains 20 SIG and 20 EXE events. With an explicitly selected reference key, hashes, signatures and legacy Merkle comparisons match the reference material. That uses the old implementation’s encoding and odd-node duplication, not JCS or strict RFC 6962 conformance. The first PrevHash boundary, authenticated batch metadata and original external anchor remain unresolved. Key-owner identity is not established. The expected overall result is INDETERMINATE, with replay exit code 2.
