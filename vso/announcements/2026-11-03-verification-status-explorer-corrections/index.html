VSO updates verification-status disclosures and the public Explorer

VSO is publishing a consolidated record of 23 pull requests merged across 23 repositories on 3 November 2026 (JST). This website update aligns the current VAP source reference, the public Explorer GUI and the announcement archives with those merged revisions.

Scope and verification status

These are disclosure corrections, bounded implementation repairs and first-party checks. They do not establish full VCP/VAP conformance, certification, production readiness or independent third-party reproduction. Experimental extensions remain unadopted; independent reproduction is not established. A local test reported in a PR, first-party CI, this website deployment check and an independent new execution are different records.

Current VAP text and digest

VAP PR #45 adds the previously published commercial-claim withdrawal directly beside historical G-2 and records the disposition. The original historical text is retained. The withdrawn contract figure is not a verified commercial result and is not replaced with zero. The document remains v1.2.0 Draft 3; no normative requirement changed. The source correction is dated 2 November; this website notice is dated 3 November, after the merge.

Public Explorer: inspect supplied links without overstating verification

GUI PR #22 stops unknown Trace IDs and event IDs from falling back to unrelated demo records. Search and detail requests are bound to the selected Trace ID and data mode; prior results are cleared during a new request, cancellation or failure. The Hash Chain page distinguishes LINKS_MATCH, LINK_MISMATCH, INSUFFICIENT_DATA and INVALID_DATA. Equality of supplied hash strings does not recompute event hashes or establish signatures, a trusted external anchor, completeness or a verified genesis boundary. NOT_CHECKED and NOT_ESTABLISHED remain visible.

Authentication, proof boundaries and conservative outcomes

FIX, IBKR and Nasdaq reference checks, and the transparency backend, stop treating unauthenticated local consistency as complete verification. Known contradictions and indeterminate trust remain distinct. CAP-SRP tightens proof binding and serialized verification; the Cloudflare and TradingView examples check configured credentials before ingestion or writing. TradingView retains failed in-memory anchor batches but does not establish persistence across restarts. The supervision-node example rejects unverified proof results and requires API authorization. These repository fixes do not imply that every reference service has been deployed or independently assessed.

Historical documents, assurance language and reporting routes

VCP specification, SDK/conformance guides, CAP documents and reference materials clarify historical status, license scope and unsupported assurance statements. The payout demo no longer presents a public prefix as a verified signature; the GDPR demo uses a reserved example address. vso-docs withdraws a confidential report from the current tree and replaces editable certificate forms with clearly historical forms; this is not a claim that repository history or caches have been erased. Explorer API #27 updates the security-reporting policy link, not API verification behavior. The three broker landing pages require analytics consent.

What the checks mean

The merged GUI PR links successful first-party CI for its final reviewed head, including browser, subpath, accessibility and container checks. For this static publication, we separately ran the GUI lint, production build and 52 Node tests, then checked the deployed bytes and desktop/mobile display. Container checks do not make GitHub Pages run the container or inherit its nginx headers. The existing Evidence Demo API and its fixed inputs are retained: local checks and full evidence status remain separate. Other PRs include a mixture of first-party CI and reported local tests; the source records below retain those distinctions. No combined cross-project test count is claimed.
