VSO更新SDK指南、公开Explorer与研究实现维护记录

本次11月28日更新涵盖六个仓库已合并的11个PR，并单独说明尚未合并的Receipt上下文实验。公开Explorer GUI从文中固定的源码版本更新；本次网站发布不部署另行管理的API运行环境。

实验性扩展与修正提案仍未采纳，独立第三方复现尚未成立。自有CI、GUI发布和独立复现是不同的结果。固定发行物、已签名数据与历史测试记录均予以保留。

1．VeraSnap Verify SDK：明确保险分流示例的条件

VeraSnap Verify SDK #8 已合并至 8271efcf4b3eee0c633435ab789e1ed14c176205。快速审核示例不再仅依据绿色结果，还要求 media_verified、signer_key 检查为passed且代码为 known，以及 account_ref 与保险机构已认证理赔记录中的预期账户一致。

即使照片检查被跳过，或使用无硬件证明的手动注册密钥，也可能得到绿色结果。示例条件不等于保险赔付决定，也不证明照片中的场景真实。缺少证明、照片或信任文件时，CLI返回输入错误退出码 3。Merkle包含只将一个事件与提供的根进行核对；未签名的删除计数提示不能证明完整拍摄历史。

上游安装指南固定到开发版本 1f1289ef21fea84393d42a36ee10152c25cae70e。最新main在每个Python版本下通过196项测试。固定 v0.1.0 的125项记录与后续186项记录分别保留，固定发行版不包含本次修复。参见版本与已知问题列表。

2．VCP SDK：保留策略标识，但不扩大签名覆盖范围

VCP SDK #26、main 1e75820e954eda7232bc57eb21037efaa1cbf1ba 在 vcp seal 输出事件时保留可选的顶层 PolicyIdentification 对象。签名前检查该对象的 PolicyID 是否与 Header.PolicyID 一致。

保留对象不等于将其纳入签名。 事件签名覆盖基于Header、Payload及可选前一哈希计算的哈希。策略块中的符合性tier和注册详情仍是未签名元数据。复制该块不证明注册、认证或策略内容的真实性。

安装指南指向开发版本 59860c5d3180ac8bdc2e8b9df500af7ae2c162f7。软件包版本仍显示 0.1.0，应以提交SHA区别于不变的 v0.1.0 标签 cc6c468。保留 28d46e8 时点的seal恢复记录。即使预先暂存两个输出文件，两次替换也不是一个原子事务。

3．公开Explorer GUI：保留时间精度并标明判定来源

公开Explorer GUI从 3627b075dcb0aadf42f01794edb1d3f77ef3f120 更新。#45 在UTC显示中保留输入ISO时间的小数秒，包括时区偏移导致日期变化的情况。VERIFIED 显示为 Verified (API-reported)；缺失或未知状态显示为 Unknown，不再作为Pending处理。

#41 和 #44 更新运行时与开发依赖。显示API报告的结果不等于浏览器独立验证事件。GUI发布本身不能证明远程API运行最新main，也不能证明所有显示记录的真实性。

4．Explorer API：区分源码修复与运行环境部署

API main 6004d377ca5f1881857220f1956962c92554e36e 包含：#44 统一事件摘要、详情与证书数据中的纳秒时间；#45 让recent按最新事件优先排序，并等同处理UUID／trace的十六进制大小写；#46 修正软件包版本报告并链接公开开发指南。

root与health响应使用源码的软件包版本 1.1.0，替代旧的硬编码值。这不是新标签发行版。上述为已通过自有CI的仓库变更。本次网站更新不部署另行管理的API运行环境。 现有API与GUI的 v1.0.0 标签不变。

5．VCP事件CLI：区分省略枚举与空数组

VCP规范仓库 #47、main 03bbfe5f68ec9a81f32108146a3ebe43d0800541 修复使用自定义schema时ERASURE可选字段 Scope.EventIDs 的检查。字段存在时，数组必须非空，并与数量及首末ID一致；省略字段时保留原有处理。默认schema已要求至少一个条目。

变更仅涉及本地CLI与回归测试，不修改规范正文或schema，也不增加签名或Receipt密码学验证。main自有CI通过41项测试；此前40项记录保留。

6．CAP-SRP：按attempt ID核对本地覆盖，并保持演示会话关联

CAP-SRP #8 将统计中仅比较数量的检查改为现有的attempt ID匹配。若部分日志包含一个孤立结果及另一个尚无结果的试行，不再因数量相等就判定完整。pending表示提供的试行中没有匹配结果的数量。

#9 为CLI及Custom Demo生成的成功、拒绝和错误结果保留原试行的session ID，使按会话筛选时仍能保留试行与结果的配对。包含两项修复的main 20b24a4e846c25721b728266bc183bd831bef77b 通过全套417项测试。另行运行的365项回归测试是其子集，不能再加到417项之上。

这些是本地PoC与合成演示的修复，不证明从未记录的请求已被捕获、来源集合完整、外部锚可信或CAP／VAP符合性已成立，也不表示已部署另一个公开CAP-SRP服务。

单独列出的未合并工作：七个Receipt上下文案例的固定replay

Draft PR #45 在HEAD 45c99c2e5b5700ee8d2841b89fa0471b84572ecc 仍为草案且未合并。固定replay包覆盖拟议22个案例中的7个。自有Python和Go实现各产生8项判定：在声明且获授权的服务上下文下确认包含5项、缺少适用密钥授权2项、规则上下文歧义1项。比较的报告各字段一致。

实验重复使用两个合成Receipt、两叶树和受限A1条目构造。其余15个案例未执行；来源完整性、历史一致性、签发时间、位置／大小及本地VCP批次完整性仍未评估。两个实现均来自本次实验，一致结果不代表外部独立复现或完整SCITT-VCP配置文件的互操作性。

11月27日公告作为此前核查记录保留，包括当时的“执行0项”说明。本日期公告补充后来确认的分支状态，不将草案合并到main、不采纳拟议要求，也不改变已发布的 -07 基准。
