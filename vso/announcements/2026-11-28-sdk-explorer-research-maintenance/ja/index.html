VSO · 2026-11-28 · SDK・EXPLORER・研究実装の保守

VSO、SDK案内・公開Explorer・研究実装の保守記録を更新

11月28日付で、6リポジトリのマージ済み11 PRと、別の未マージReceiptコンテキスト実験を整理します。公開ExplorerのGUIは記載したソース版から更新します。別管理のAPI実行環境は、今回のサイト公開では更新しません。

実験的拡張・修正案は未採択で、第三者による独立再現は未成立です。自社CI、GUIの公開、独立した再現実行は別の結果として扱います。固定配布物、署名済みデータ、過去の試験記録を保持しています。

1．VeraSnap Verify SDK：保険向け振り分け例の条件を明確化

VeraSnap Verify SDK #8 は 8271efcf4b3eee0c633435ab789e1ed14c176205 にマージ済みです。迅速審査への振り分け例では、緑の判定だけでなく、media_verified、signer_key の passed／known、保険会社の認証済み請求記録から得た期待アカウントと account_ref の一致を確認します。

写真の検査がスキップされた場合や、ハードウェア証明のない手動登録鍵でも、緑になる場合があります。例示した条件は保険金の支払判断でも、写っている状況が真実であることの証明でもありません。証明・写真・信頼ファイルが見つからない場合はCLIの入力エラー、終了コード 3 を返します。Merkle包含は一つのイベントと提示された根の照合であり、未署名の削除件数情報から撮影履歴の全量を確認できるわけではありません。

上流の導入手順は開発版 1f1289ef21fea84393d42a36ee10152c25cae70e に固定されています。最新mainの自社CIはPython各版で196件成功です。固定 v0.1.0 の125件と、後続の186件は別時点の記録として保持し、固定リリースには今回の修正を含めません。版と既知問題の一覧も参照できます。

2．VCP SDK：ポリシー識別情報を保持し、署名範囲は拡張しない

VCP SDK #26、main 1e75820e954eda7232bc57eb21037efaa1cbf1ba は、vcp seal の出力へ任意のトップレベル PolicyIdentification オブジェクトを保持します。署名前に、このオブジェクトの PolicyID と Header.PolicyID が一致することを確認します。

保持することと、署名で保護することは別です。 イベントの署名が覆うのはHeader・Payload・任意の直前ハッシュに基づくハッシュです。ポリシーブロックの適合tier・登録詳細は未署名のメタデータのままです。コピーしただけで、登録・認証・ポリシー内容の真正性が確認されたとは扱いません。

導入案内は開発版 59860c5d3180ac8bdc2e8b9df500af7ae2c162f7 を参照します。パッケージ表記は 0.1.0 のままなので、不変の v0.1.0 タグ cc6c468 とコミットSHAで区別します。28d46e8 時点のseal復旧記録は保持します。2ファイルを一時領域へ準備しても、2回の置換が一つの原子的な更新になるわけではありません。

3．公開Explorer GUI：時刻の精度を保持し、判定の出所を表示

公開Explorer GUIを 3627b075dcb0aadf42f01794edb1d3f77ef3f120 から更新します。#45 は、ISO時刻に含まれる小数秒をUTC表示でも保持し、時差で日付が変わる場合にも対応します。VERIFIED は Verified (API-reported)、欠落・未知の状態はPendingとせず Unknown と表示します。

#41 と #44 は実行時・開発用の依存関係を更新しています。APIが返した判定の表示は、ブラウザーによる独立したイベント検証ではありません。GUIを公開しただけで、接続先APIが最新mainを実行していることや、表示された全記録の真正性までは確認できません。

4．Explorer API：ソースの修正と実行環境への反映を分離

API main 6004d377ca5f1881857220f1956962c92554e36e は、#44 でイベント要約・詳細・証明書データのナノ秒時刻を揃え、#45 でrecentを最新順にし、UUID・traceの16進文字の大小を同等に扱います。#46 はパッケージ版の報告と公開開発ガイドへのリンクを修正します。

root・healthの版は、古い固定値ではなくソースのパッケージ版 1.1.0 を使います。新しいタグ付きリリースではありません。これらは自社CIが成功したリポジトリ上の変更で、別管理のAPI実行環境は今回のサイト更新では配備しません。 既存のAPI・GUIの v1.0.0 タグは不変です。

5．VCPイベントCLI：列挙の省略と空配列を区別

VCP仕様リポジトリの #47、main 03bbfe5f68ec9a81f32108146a3ebe43d0800541 は、カスタムスキーマを使ったERASUREの任意項目 Scope.EventIDs の検査を修正しました。項目があれば空配列を拒否し、件数と先頭・末尾IDの一致を確認します。省略時の扱いは維持します。既定スキーマは既に1件以上を要求しています。

変更はローカルCLIと回帰試験だけです。規範本文・スキーマの変更でも、署名やReceiptの暗号学的検証の追加でもありません。mainの自社CIは41件成功で、以前の40件の記録は残しています。

6．CAP-SRP：ローカルの対応関係をIDで照合し、デモのセッションを保持

CAP-SRP #8 は、統計の件数一致だけの確認を、既存のattempt IDによる照合へ揃えました。ある試行の結果と別の未完了試行が一つずつ含まれる部分ログを、件数が等しいだけで完了扱いにしません。pendingは、提示された試行のうち対応する結果がないものの数です。

#9 は、CLIとCustom Demoで生成する成功・拒否・エラーへ、元の試行のsession IDを引き継ぎます。セッションで絞り込んでも試行と結果の組を保持できます。両修正を含むmain 20b24a4e846c25721b728266bc183bd831bef77b は全417件成功です。別の回帰試験365件はその部分集合なので、追加の365件として合算しません。

ローカルのPoCと合成デモの修正です。最初から記録されなかった要求の捕捉、記録元の全量、外部アンカーの真正性、CAP／VAP適合を確認したものではありません。別のCAP-SRP公開サービスへ配備したとも扱いません。

未マージの別作業：Receiptコンテキスト7ケースの固定replay

Draft PR #45 はHEAD 45c99c2e5b5700ee8d2841b89fa0471b84572ecc で、引き続きDraft・未マージです。固定replayパッケージが22ケース中7ケースを扱います。自社のPython・Go実装が各8判定を行い、宣言された認可済みサービスコンテキスト下での包含確認5件、適用される鍵の認可情報不足2件、ルールの曖昧さ1件を記録しました。比較対象のレポートは全フィールドで一致しました。

2枚の合成Receipt、2葉の木、限定したA1入力構成を使い回す実験です。残り15ケースは未実行で、記録元の完全性・履歴の整合性・発行時刻・位置とサイズ・ローカルVCPバッチの整合性は未評価です。両実装は同じ実験から作られており、一致は外部の独立再現やSCITT-VCPプロファイル全体の相互運用を示しません。

11月27日のお知らせは「実行0件」を含め、前回の確認記録として保持します。今回の日付付き記事で、その後確認したブランチの状態を追記します。Draftをmainへ取り込むこと、提案要件の採択、公開済み -07 の基準変更ではありません。
