VSO · 2026-11-27 · SOURCE MAINTENANCE & EVIDENCE REVIEW

VSO reports SDK seal recovery, Explorer source updates and 85 incident records

This 27 November notice groups merged source and documentation changes into four areas. CI results belong to the stated commits; they are not independent reproduction or proof of public deployment.

Experimental extensions and proposed repairs remain unadopted; independent third-party reproduction has not been established. The VAP specification reference and hash are unchanged. Fixed releases, signed data and historical test records are retained.

1. VCP SDK: validate batch policy and recover seal outputs

PR #25 is merged at cb6a69ee5d5c6b666825aaf721c30f8f9ad45636. Before signing, vcp seal now checks that all input events have one Header.PolicyID and that an explicit --policy-id agrees. It stages the event file and AnchorRecord and attempts to restore the original event output if the second replacement fails.

These two replacements are not one atomic transaction. Readers must wait for successful completion. Crashes, failed rollback or cleanup warnings can require inspecting retained staging and recovery files. The fix is not a guarantee against every interruption.

The current installation guide already points to implementation revision 28d46e8491f6ff819f1cfe7c31895ed7ad7df3ff. The historical v0.1.0 tag at cc6c468 is unchanged and lacks this repair. Package metadata remains 0.1.0; the guide uses --force-reinstall. A dated addition to the release description is not a new release. The version matrix adds 27 November information while preserving its 26 November snapshot.

2. Explorer: source maintenance is separate from deployment

API main 1f708ada55f12e609c343264201603ccc4f1568c includes #42: /v1/health now aliases the existing /health response and uses the existing /v1 rate limit. #36 updates Express to 5.3.0 while preserving UTF-8 form handling; #39 updates Stylistic to 6.0.1.

GUI #39, main 2c9868334ffd66888d28ab8a309d0c999fa82749, aligns Vite 8.3.8, React plugin 6.3.0 and the component-test build, including explicit esbuild 0.28.2. This is build-tool maintenance, not a new cryptographic capability.

This publication does not redeploy the public Explorer. A successful source build, GitHub Pages deployment or health response does not establish that a separately hosted API or the public GUI bundle runs these revisions. The existing API/GUI v1.0.0 tags remain unchanged.

3. VCP event-validation CLI: report unresolved schemas as configuration errors

PR #46, main 81513e5ddb600c20551b975e6c1e0ba126b67c54, treats unresolved JSON Schema references as configuration errors with exit code 2. It avoids leaving partial batch verdicts on standard output when that error occurs. Ordinary input and file-error handling is retained.

The v1.2 and benchmark documentation also updates its EU business-clock reference. Normative text, schemas, scoring rules and the fixed release are unchanged. This is an event-validation CLI repair, not added signature or Receipt verification.

Separate unmerged work: Draft PR #45 discusses Receipt context and historical rule selection. It remains unmerged and unadopted: 22 planned cases, zero executed cases, not published executable vectors or a successful interoperability result.

4. Incident library: seven additions and two follow-ups

The library now has 85 records, up from 78. Seven new entries are listed below; follow-ups to two existing records are separate. This collection includes reports, studies and procedural/legal material. It is not a count of 85 confirmed AI attacks or of failures that VAP could have prevented.

  • V1123GT13CHECKPOINT · GT13 / Check Point：GreyNoise reports intrusion activity against management servers. Its account of LLM or agent use remains a suspicion; the bulk certificate task failed, and the record does not generalise one victim’s outcome to all targets.
  • V1120BABIDIGHOST · BabidiGhost：SOCRadar reports a jailbroken Hermes agent framework and differentiates observed outcomes. Its analysis, Secutec’s statements and reporting are kept separate; model identity and differing municipal counts are not independently established or reconciled.
  • V1123VAORGROK · Grok state-court actions：Virginia and Oregon announced separate lawsuits. Allegations about images and safety statements are not court findings; the record does not infer an absence of audit trails.
  • V1124BACS · Swiss BACS reports：The 24 November official statement is distinguished from the director’s later interview reporting five cases and four successes. The difference from the earlier statement that all known attacks succeeded remains unexplained.
  • V1124MINIMAX · MiniMax URL access：MiniMax’s own disclosure about URLs in forwarded API requests is distinguished from researchers’ observations and provider responses. It is a new source disclosure, not a repeat of the Together AI record.
  • V1125AIOFFICE · EU AI Office information requests：The Commission described requests to OpenAI and Anthropic and assessment of their replies. This is a procedural record, not a finding of infringement or confirmation of a particular incident.
  • V1125DELOITTEWA · Deloitte / Western Australia：Reporting describes suspension for up to three months from two common-use arrangements. It does not establish a permanent, government-wide ban or an absence of records.

Existing-record follow-ups: V1007A, the Australian Medicare statistics service, adds review and parliamentary/reporting developments with source-access limits; it does not newly establish that individual patient data was exposed. V1118MUSE adds the UK launch as reported by Reuters and a separate FCA statement that names no company. Neither is counted as a new incident.

Official accounts, related-party explanations, reporting and VSO’s interpretation remain separate. The CIA/ODNI OSINT item stays on hold, and the Together AI repeat is not republished as new. VSO’s interpretation: these records inform questions about observation boundaries, authorisation and evidence handling; they do not show that VAP controls execution or solves the reported harms.
