# 実サービスの画面を使う確認手順

この手順は未実行です。ChatGPT・Claude・Gemini等の現行画面でRecorderが動作することを、
合成ページの自動試験から推定しないために、別の確認記録として用意しています。
実施したサービス・画面・ブラウザ・操作だけを結果に含めてください。

## 入力と準備

機密情報のない新しい会話を使い、サービス名、実施日時とタイムゾーン、OS、Chrome版、
拡張版、使用したZIPのSHA-256を記録します。既存の会話や個人情報は試験に使いません。
対象サービスでの通常の利用権限を使い、アクセス制限や人間確認を回避しません。
ログインや拡張の読み込みができなければ、その段階を `BLOCKED` として記録します。

合成プロンプトの例:

```text
動作確認用です。次の2行だけを、そのまま返答してください。
これは合成テキストです。
VAP recorder test 001 — 日本語・🙂
```

モデルが別の文章を返した場合も、実際に表示された回答をそのまま確認対象にします。
期待する文章をページへ挿入したり、提供者が生成した文章であると推定したりしません。
回答の生成が止まってから、本文の選択を始めます。

## 操作と確認点

| 操作 | 確認する結果 |
| --- | --- |
| 回答の本文だけを選択し、拡張アイコンから取り込む | 実際に選択した文章とプレビューが一致する。入力欄は選ばない |
| 保存前の画面を確認 | 同意は未選択で、保存ボタンは無効。取得元表示はサイトのオリジン |
| 明示的に同意して保存 | 件数が1件増え、記録庫に選択した文章が表示される |
| 同じプロファイル・同じ拡張パスでChromeを再起動 | 記録と鍵指紋が維持される |
| 記録JSONと、その書き出しに対応する照合票を保存 | 両ファイルを選んだ拡張の検証とNode検証が成功する |
| 合成記録のコピーだけを編集し、本文に文字を追加 | 改変コピーの検証が失敗する。元ファイルと照合票は保持する |
| 別の合成回答を追加して、新しいJSONと照合票を書き出す | 新しい組合せは成功。古い照合票を新しい記録へ当てると不一致になる |

Nodeでの検証:

```sh
node verify.mjs observations.json --checkpoint checkpoint.json
```

自動試験では拡張のactionをDevTools経由で起動しています。実際のツールバーを手で操作した場合は、
その方法を記録してください。単にページの本文を読み出せたこと、公開トップページを取得できたこと、
取得関数だけを実行できたことは、上記の拡張全体の成功として扱いません。

## 結果の記録様式

次の項目を、合成データと必要最小限の画面証拠とともに残します。個人名、メールアドレス、
別の会話、認証情報が画面へ入る場合は、共有用の画面証拠に含めません。

```text
実施日時・タイムゾーン:
サービス・対象画面:
OS / Chrome版 / 拡張版 / ZIP SHA-256:
操作方法（手動 / 自動）:
実際に入力した合成プロンプト:
選択した回答本文:
拡張ロード: PASS / FAIL / BLOCKED / NOT_TESTED
取得・プレビュー・同意・保存: PASS / FAIL / BLOCKED / NOT_TESTED
再起動・鍵指紋・記録保持: PASS / FAIL / BLOCKED / NOT_TESTED
書き出しと検証: PASS / FAIL / BLOCKED / NOT_TESTED
改変と旧照合票の拒否: PASS / FAIL / BLOCKED / NOT_TESTED
観測したエラー・制限:
```

1サービスで成功しても、他サービス、別OS、別Chrome版、ストリーミング途中、会話分岐、
非表示ツール実行、未選択の会話まで確認済みとはしません。
この試験でも、提供者の真正性、信頼できる時刻、外部アンカー、会話全体の完全性、VAP適合は確立しません。
