Receiving-system evaluation · alpha

VeraSnap Verify SDK

A Python SDK for receiving photos and evidence. Evaluate signature, timestamp-evidence and key-enrollment checks. Its API may change, and it has not been independently audited.

Read current SDK guidance and limitations

Key enrollment requires separate preparation. Taking a photo with the consumer app does not enroll the device key with an insurer. In the SDK, evidence from an unknown key remains partially verified even when the signature and timestamp are valid.

The Capture SDK for embedding capture functionality in a company's own app is at the design stage. It is separate from the published Verify SDK.

EVALUATION

Evaluate one workflow on a small scale.

Define the scope and success criteria before collecting production data. Include how your workflow will handle unknown results.

  1. Choose the scope

    For example, one step in receiving loss photos. Identify the submitter, receiving reviewer and current review method.

  2. Run through with test data

    Use synthetic data or test photos you are authorized to use to evaluate capture, original-file retention, evidence receipt and verification.

  3. Include failures and unverified items

    Evaluate whether the results are useful for operational decisions, including altered files, unknown keys and missing timestamp evidence.

  4. Agree on adoption conditions

    Confirm licensing, storage locations, access permissions, retention periods, costs and support scope individually.

Questions about evaluation

Can it automatically identify AI-generated images or insurance fraud?

The product does not guarantee that image content is true or automatically establish whether fraud occurred. Use signature, hash, timestamp-evidence and enrolled-key findings alongside other investigative material.

Can it be embedded directly in an insurer's existing app?

The receiving-side Verify SDK is available for evaluation as a public alpha. The Capture SDK for embedded capture functionality is at the design stage. Integration, key enrollment and operational conditions require separate consideration.

How do we confirm business-use terms?

The public app EULA contains provisions about personal and non-commercial use. Confirm business-use permission and licensing conditions with the team in advance. The Verify SDK's Apache-2.0 license is separate from the app license.

Does opening an evidence pack in a browser verify everything?

VeraCheck Web is a beta viewer for display and limited checks. Showing that Merkle proof or TSA information is present is different from fully verifying it cryptographically. Check the verifier version, supported checks and unverified items.
