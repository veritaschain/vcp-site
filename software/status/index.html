VeraSnap Verify SDK: insurance routing and file-input failures

PR #8 is on main 8271efcf4b3eee0c633435ab789e1ed14c176205. The README selects installation revision 1f1289ef21fea84393d42a36ee10152c25cae70e. In the insurance-routing example, a green result alone is insufficient: the media must have been verified, the signer-key check must pass with known hardware-attested enrollment, and the signer account must match the expected account from the authenticated claim record. Manual enrollment, absent media or an account mismatch must not enter that example's fast route. This is an integration example, not a claim-acceptance guarantee or a new universal green-result rule.

Missing proof, media or trust files are handled as CLI input errors with exit code 3. Merkle inclusion is limited to the supplied event; it does not establish a complete capture history, and deletion hints remain unsigned. First-party CI recorded 196 passed on each of Python 3.10, 3.12 and 3.13. The fixed v0.1.0 release retains its 125-test record; the later 186-test snapshot below is also retained. These changes are not retroactively included in that release.

VCP SDK: retain policy metadata without overstating signature coverage

PR #26 is on main 1e75820e954eda7232bc57eb21037efaa1cbf1ba. The current installation guide pins 59860c5d3180ac8bdc2e8b9df500af7ae2c162f7; see the updated installation command. vcp seal preserves optional top-level PolicyIdentification and checks that it is an object whose PolicyID agrees with Header.PolicyID before signing. Invalid input exits with code 3 before replacing the output pair. The retained registration metadata, including ConformanceTier, remains unsigned. Retention is not authentication, and this repair does not expand the signature contract. The two output replacements are still not one atomic transaction.

VCP SDK: policy checks and recovery of the two seal outputs

Merged PR #25 is on main cb6a69ee5d5c6b666825aaf721c30f8f9ad45636. The installation guide now pins implementation revision 28d46e8491f6ff819f1cfe7c31895ed7ad7df3ff. The historical v0.1.0 tag remains at cc6c4689c312662dcd9157f3270e6ed8f2c509cb and does not contain this repair. Package metadata is still 0.1.0; follow the guide's --force-reinstall instruction when replacing a same-version installation. The existing release description gained a dated 27 November installation note; this is not a new release.

vcp seal checks all events for one Header.PolicyID, including agreement with an explicit --policy-id, before signing. It stages the event file and AnchorRecord before publication and attempts to restore the original event output if the second replacement fails. The two replacements are not one atomic transaction. Readers should wait for successful completion. After a crash or failed rollback, stop writers and inspect the retained staging and recovery files before restoring or verifying the pair. A cleanup warning after successful publication can also leave a staging directory; use the recovery instructions rather than silently deleting it.

Before installing or sharing results

  1. Choose the use case: app proof verification, VCP event checks, Explorer demonstration or a specific VAP research experiment.
  2. Open the pinned source and known-issue notice. Record the full commit rather than the package version alone.
  3. Keep the original proof, trust configuration, release ZIP and hashes. Run a corrected revision on a separate copy; do not rewrite signed source data.
  4. Report runtime/dependency versions, actual commands, failures and unassessed checks. A successful sample does not establish all-device rollout, production suitability, certification or independent reproduction.
