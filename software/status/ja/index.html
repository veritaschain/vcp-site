VeraSnap Verify SDK：保険向け振り分け例とファイル入力エラー

PR #8 を含むmainは 8271efcf4b3eee0c633435ab789e1ed14c176205 です。README の導入対象は 1f1289ef21fea84393d42a36ee10152c25cae70e。保険向けの振り分け例では、greenだけでは自動処理へ進めません。写真本体の検証、ハードウェア認証付き登録を示す署名者鍵チェックの known・成功判定、認証済み請求記録から取得した期待アカウントとの一致を確認します。手動登録、写真未提示、アカウント不一致は、この例の簡易処理経路に入りません。これは組み込み例であり、保険請求の受理保証やgreen判定全般への新しい規則ではありません。

証明・写真・信頼設定のファイルが見つからない場合は、CLIの入力エラーとして終了コード3を返します。Merkle包含証明は提示されたイベントに限られ、撮影履歴の全件性を示しません。削除のヒントも署名対象外です。自社CI ではPython 3.10・3.12・3.13それぞれで 196テスト成功。固定 v0.1.0 の125テストと、その後の186テストの記録は残しています。今回の修正が固定リリースに遡って含まれるわけではありません。

VCP SDK：ポリシー確認とsealの2出力の復旧

PR #25はmain cb6a69ee5d5c6b666825aaf721c30f8f9ad45636へマージ済みです。導入案内は実装を28d46e8491f6ff819f1cfe7c31895ed7ad7df3ffに固定しています。既存のv0.1.0タグはcc6c4689c312662dcd9157f3270e6ed8f2c509cbのままで、この修正を含みません。パッケージの版表記は引き続き0.1.0なので、同じ版表記のインストールを置き換える場合は案内の--force-reinstallを使います。既存のリリース説明に11月27日の導入案内が追記されましたが、新しいリリースではありません。

vcp sealは署名前に、全イベントのHeader.PolicyIDが一つであることと、明示した--policy-idとの一致を確認します。イベントファイルとAnchorRecordを一時領域へ準備してから出力先を置換し、2個目の置換が失敗した場合は元のイベント出力の復旧を試みます。2ファイル全体を一度に確定するatomicな更新ではありません。読み手は処理の成功終了を待ってください。途中停止や復旧失敗が起きた場合は書き込みを止め、残された一時領域・復旧用ファイルを調べてから出力ペアを復元・検証します。出力成功後の後片付けで警告が出た場合にも一時ディレクトリが残ることがあるため、黙って削除せず復旧手順を確認します。

  4. 実行環境・依存関係・実際のコマンド・失敗・未評価項目を報告します。サンプルの成功を全端末への配信、本番適合、認証、独立再現に読み替えません。
