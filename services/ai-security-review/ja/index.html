まず、ひとつのワークフローを決める

AI提供企業、開発責任者、セキュリティ・ガバナンス担当者向けの技術相談です。例えば、顧客情報を更新するエージェント、外部APIを呼ぶ業務支援機能、承認を受けて操作するAI機能など、確認したい操作と疑問をひとつに絞ります。これらは対象を考えるための例であり、顧客への導入実績ではありません。

商業的なレビューの提供主体はVeritasChain株式会社です。相談担当の上村十勝（TOKACHI KAMIMURA）の公開案内に沿い、構成・コードのレビューと、合意した範囲での試験、証拠に基づく所見、未確認事項の整理を扱います。VSOは同社が運営する仕様開発活動です。Tokachi Kamimura — official profile and technical review scope VeritasChain Co., Ltd. — operating entity and VSO relationship

VAPやVCPを採用していない既存システムも相談できます。まず現状の構成と利用可能な記録から、確認できることを整理します。

権限・実行・証拠を照合する

実際に扱う項目は着手前に合意します。次は、そのための確認例です。

レビュー対象を選ぶための問い
観点確認する例所見に残す境界
権限・委任誰が、どの操作・対象・期間を許可したか。失効や承認後の引数変更をどう扱うか。設定文書と、実際の実行時チェックを分ける。
ツール・外部入力外部文書やツール応答を命令として扱う経路、秘密情報に触れる箇所、直接API呼び出しの経路。調べた経路と、対象外・未確認の経路を明示する。
実行結果送信、受理、完了をどう区別するか。タイムアウトや再試行時の重複をどう確認するか。応答がない場合を、成功・失敗のどちらかに決めつけない。
監査証拠記録の結び付け、欠落、改変の確認条件、ログに残る秘密情報、信頼する鍵・観測元。署名の正しさと、記録された内容の真実性・全量性を分ける。

事前に整理したい場合は、AIエージェントのセキュリティガイドと証拠検証の用語集を参照してください。VSO — AI agent security: permissions, tools and evidence

確認に必要な資料と共有方法

初回の連絡は、公開できる概要だけで構いません。秘密鍵、APIトークン、顧客情報、生の会話・実行ログは添付しないでください。共有が必要な資料、閲覧者、共有経路、保管・削除条件は、対象範囲と一緒に決めます。

  • 対象と責任者：確認したい操作、関係システム、環境管理者、対象外のシステム。
  • 構成とコード：データ・権限の流れ、レビューするソースの版、依存サービス、関連する設定の説明。
  • 期待する動作：承認・拒否・記録障害・結果不明時に、何を許し、何を止めるか。
  • 確認用の材料：機密情報を除いた記録、合成入力、エラー例、利用できる検証環境。

資料が揃っていない段階では、不足する材料とその影響から整理します。資料がないことを、問題がない証拠にはしません。製品ごとの公開情報はセキュリティ・データ取扱い案内で確認できます。

成果物は、所見と根拠を追える形で合意する

次は成果物の構成案です。提供する項目、詳細度、形式、追加確認の有無は案件ごとに合意します。

  • 対象範囲の記録：確認した版・環境・操作・期間と、対象外の範囲。
  • 構成・権限の整理：承認、ツール実行、観測記録の関係と、確認した境界。
  • 根拠付きの所見：観測した事実、参照するコード・記録、影響する条件、未確認事項。
  • 合意した試験の記録：入力、手順、期待結果、実際の結果、差分。実施しなかった試験も区別。
  • 改善候補：変更案、優先する理由、再確認する条件。実装・運用変更は別途範囲を決める。

所見の記載例（架空の例）：「模擬環境の更新要求では送信記録があるが、応答喪失後の結果照会記録はない。API側の処理結果は不明で、完了とも失敗とも確定できない。照会手順と再試行条件を追加で確認する。」これは報告形式の説明であり、実在システムの評価結果ではありません。

相談からレビューまでの進め方

  1. 概要を共有：ワークフロー、解決したい疑問、希望成果物、希望時期を送ります。
  2. 実施条件を合意：提供可否、対象・対象外、資料、成果物、費用、日程、共有・保管条件を確認します。問い合わせだけで着手や納期が確定するものではありません。
  3. 構成・コードを確認：合意した資料と版を基に、権限・実行・証拠の対応を整理します。
  4. 合意した試験を実施：必要な場合のみ、権限を確認した管理下の環境で、対象・操作・実行者・停止条件を決めて実施します。第三者の本番サービスへの無許可の試験は含みません。
  5. 所見と未確認事項を共有：観測結果と推測を分け、必要な追加確認・再試験を相談します。

依頼者が管理する環境で実行する場合も、誰が準備・操作・設定変更・支援を行ったかを記録します。VSOによる実行や実質的な支援を、独立した第三者による再現に読み替えません。

技術レビューと公開研究の位置づけ

このページは相談案内です。規範要件、既存実装、署名済みデータ、固定配布物、K3や過去の試験記録を変更するものではありません。

実験的拡張・修正案は未採択で、独立した第三者による再現は未成立です。自社CI、内部の合成試験、保存済み証拠の再検証、独立した環境での新規実行を分けて扱います。商業的な技術レビューの実施自体も、VAPの独立再現や正式採択を意味しません。

技術レビューは法律相談・適合性認証ではなく、すべての脆弱性の発見、本番安全性、全操作の捕捉を保証しません。記録の署名が正しくても、内容の真実性や、その操作が正当に認可されていたことは別に確認が必要です。研究・規範・製品の状態は公開版・既知問題と検証の限界で確認してください。VSO — verification scope and limitations
